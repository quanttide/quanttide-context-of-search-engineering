# 语料关联与去重实验报告

> 草稿，待审。

## 意图

四十六个领域仓、两万多段内容，同一段话在两处出现、而且已经写得不一样时，没人知道。

要的是三件事：**找重样的、问一句话就翻到、找出横跨多个领域的主题**。

判据一句话：它只说「像」，不说「对不对」——「这两段算不算重复」机器能判，「这条重复要不要改、以哪个为准」只有人能定。

## 结果

语料取本地 `~/repos/quanttide/domains/`（各仓 `docs/*` 子模块已拉全），切出 **22811 条** 20 至 900 字的片段，来自 38 个有内容的领域仓（另 8 个是只有 README 的占位仓）。用本地 bge-m3 向量化成 1024 维，全程离线。

**找重复**：每条片段取最近的 10 条近邻，余弦 ≥ 0.90 才留（阈值先写死、跑完不改）。查出 **586 对**高相似，涉及 **946 / 22811 = 4.1%** 的片段；其中跨领域 **72 对**（72 / 586 = 12.3%）。

**建索引**：`search.py "<主题>"` 返回最相近的片段与出处。实测全量精确检索 **13.6 毫秒**一次，所以没上 ANN 索引——在这个规模上引近似索引是白加复杂度。两项校验：自洽 50 / 50（拿片段查它自己，top-1 就是本人），与找重复互证 72 / 72（跨域那 72 对里，B 都落进 A 的 top-10）。**但两条链用的是同一批向量，这只证明链路通，不证明召回好。**

**聚类**（找关联）：球形 k-means，k=200。查出 200 个簇，其中 199 个算「跨域」——门槛形同虚设。抽检反而给出正确的方向：领域数高的簇在聚「怎么写」（各仓自述、清单条目、字段说明），领域数低的簇才是真主题（个税汇算、中华文明、法人记忆、小说文本，4 / 4 命中）。

**语料指纹**：每份产物记 md5 与条数，下游先核再算。实测改一个字节就会被拒（退出码非 0 并指名是哪一项）——因为语料是活的，跑完当口复跑，片段数已经从 22811 变成 22812。

## 边界

**它只说像，不说对不对。** 586 对里哪些该动、哪些本该存在，是人的活。

**重复不等于问题。** 领域划分体系是去中心化的，元领域只是定义的**起点**、不是唯一源头。asset 里展开 meta 的概念是设计如此，不是债。偏偏这两种在向量上长得一样——分不开。所以判读只能判「能不能同时成立」，判不了「谁是谁的上游」。

**出现领域越多越可能是模板，越少越可能是真关联。** 这条是本次最值钱的产出，而且是数据推翻了最初的判据：一条内容同时出现在二十个领域，多半是每个域都得写一遍的套话（「本域是干什么的」）；只在两三个领域出现的，才可能是真关联。

**判读不能与检索同源。** 检索用 bge-m3 判「像不像」，判读若也用同一族模型，两边会朝同一个方向错，那个一致性是假的。

## 三组化：同一段文本的分身

把「同一段文本的多份副本」按横跨几个领域分三组，看跨域重合究竟是债还是设计。

做法：阶段 1 那 586 对近邻对（余弦 ≥ 0.90）建成无向图，取连通分量当「分身组」，按每组的领域跨度归类。产出 `copy_groups.tsv` 与 `copy_groups_stats.json`。

**结果：435 组、946 条片段。**

| 组 | 跨度 | 组数 | 片段 |
|:--|:--|--:|--:|
| 一 | 只跨 1 个领域 | 378 | 815 |
| 二 | 跨 2–9 个领域 | 57 | 131 |
| 三 | 跨 ≥10 个领域 | **0** | **0** |

**组三为空，不等于没有模板。** 0.90 抓的是逐字近同；模板被抄到别的仓时总会改几个字，一改就掉出阈值。拿关键词直接数一遍就知道：`原子提交` 横跨 7 个领域、`最小干预` 6 个、`文档格式章程` 5 个。**模板确实在，只是跨度 2 到 7 个领域，不是「所有领域」**——抄有链条，只覆盖一部分仓。

### 组二那 57 组是什么

逐组读过，分三类。

**一、规矩与模板（17 组）——该归口。** 同一条规矩散在几个仓里各写一份：

| 组 | 跨度 | 是什么 | 归口候选 |
|:--|:--|:--|:--|
| g000 | algorithm, code, connect, growth | AGENTS.md 的「人机协作范式」段 | 元工程 |
| g001 / g002 | execute, project / org, think | 章程条文模板（解释权、章程效力） | 议事管理 |
| g003 | agent, work | spec / contract 的语汇定义 | 元工程 |
| g004 | auth, pay | 决策记录文件命名规矩（英文小写连字符、不带头日期） | 文档工程 |
| g005 | code, work | 判据分类 rule / agent / human | 执行管理 |
| g006 | code, work | 工具箱职责声明（「以规格为准，本库只做表达」） | 元工程 |
| g007 | credit, work | AGENTS 的「措辞严格使用既有术语」段 | 元工程 |
| g028 / g029 | auth, pay | CI 触发规则与权限说明 | DevOps 工程 |
| g030 | auth, pay | 决策类目清单 | 文档工程 |
| g032 / g051 | code, think / pay, project | 子模块提交顺序 | 元工程 |
| g037 | course, devops | SemVer 版本规范 | DevOps 工程 |
| g043 | delib, pay | 路线图组织模板 | 项目管理 |
| g047 | media, pay | 构建验证步骤 | DevOps 工程 |
| g053 | product, strategy | 目录结构模板（apps / packages / examples） | 元工程 |

右列只是候选。**归口是领域判断**——哪件事该由哪个域出正本、别的域改引用，得领域自己拍板；本实验只给出「同一条规矩现在散在哪些仓」这个事实，以后改一处就够。

**二、概念的定义与展开（7 组）——设计如此，不是债。** g021–g027 全部落在 asset 与 meta 之间：九宫格、资产构成、Context 的定义。领域划分体系是去中心化的，元领域只是定义的起点，下游域展开上游概念是本来的样子。

**三、同一段内容出现在两处（约 33 组）——要人判。** 例如 g033–g036（校企合作内容同时写在课程与写作）、g054–g056（小说点评）、g010–g020（智能体工程与软件工程之间的技术叙述）。这类是不是债，得逐条看原文。

## 下一步

组二第三类那 33 组要人判——它是不是债，机器分不出来，只能把原文摆出来。

组三的判据要换。按「≥10 个领域」筛是空的，因为模板的形态是**同形不同词**，不是同一段文本。要出模板清单，路子在阶段 2 那些高领域数的簇里，或改用关键词与形态匹配。

找关联若继续做，路线要改：**用检索，不用聚类**。想知道某主题在哪几个领域出现，直接查，别让它猜。
