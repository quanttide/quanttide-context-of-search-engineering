# 新手教程：搜索的最小循环

这个循环是「改进搜索算法的元系统」的最小实体：**评测发现短板 → 改一条策略 → 重跑评测 → 用数字说话**。四步跑完一轮，你就不再是碰运气调搜索。

原型在 [`quanttide-search-lab`](https://github.com/quanttide/quanttide-search-lab)（tantivy + jieba，零服务）。下文数字均为 2026-10-10 本机实测（6226 篇 Markdown）。

## 第 0 步：把原型跑起来

```bash
cargo run --release -- <仓库根> <索引目录> <查询1> <查询2> ...
```

**注意：所有查询写在同一次运行里。** 程序每次运行都全量重建并加入文档，同一索引目录跑第二次会让副本翻倍、分数漂移——实测第二次运行后同一文件在结果里出现两行、分数从 13.147 漂到 13.222，此时测出来的「改善」全是假数。

## 第 1 步：先写评测，再动代码

评测就是一张「查询 → 期望结果」的单子。新手先写三条，覆盖三类查询：

- **同义**：查「检索」，期望 `docs/tech-notes.md` 在前十（它含「索引」6 次、「检索」0 次，是现成的判据样本）。
- **拼写错误**：查 `tantsivy`，期望命中讲 tantivy 的文档。
- **语序**：查「索引 新鲜度」与「新鲜度 索引」，期望返回同一批文档。

没有这张单子，后面每一步都是盲改。

## 第 2 步：跑一轮，看短板在哪

```bash
cargo run --release -- <仓库根> /tmp/idx-clean "检索" "tantsivy" "索引 新鲜度" "新鲜度 索引"
```

实测结果：

| 查询 | 期望 | 实际 |
|------|------|------|
| `检索` | `tech-notes.md` 前十 | **不在前十**（字面匹配，只写「索引」的文档叫不醒） |
| `tantsivy` | 命中 tantivy 文档 | **无结果** |
| `索引 新鲜度` / `新鲜度 索引` | 同一批文档 | 同一批文档、同分数 ✓ |

两条真短板，一条通过。语序不敏感对我们是中性（中文查询词到就到）。

## 第 3 步：每轮只改一条策略

**改法 A——拼写纠错（同义改写之外先做这条）**：查询改写成 `tantsivy tantivy`（错词 + 正词一起查）。

```
查询「tantsivy tantivy」
    13.148  …/search-lab/docs/tech-notes.md   ← 追回
```

**改法 B——同义 OR 扩写**：查询改写成「检索 索引」。

```
查询「检索 索引」
    14.533  domains/quanttide-search/README.md
    …
    10.376  …/search-lab/README.md            ← top10 末位，tech-notes 仍未进
```

**没追回。** 原因：OR 扩写后高频词「索引」主导打分，含「索引」多的文档把目标挤出前十。

一条成功一条失败，这正是循环的意义——**改得对不对不由你感觉说了算，由重跑的数字说了算**。失败的 B 不是白做：它排除了一条路，下一轮该试字段加权、短语约束、专门的同义词表，或按日志说的「结合大模型做智能判断」改写查询。

## 第 4 步：判定，进入下一轮

- 追回了（A）：留下，评测单子上打勾。
- 没追回（B）：换下一种改法，单子照旧——单子不随策略变，否则没有可比性。
- 每轮只改一条：同时改两条，不知道功劳是谁的。

## 为什么必须先有评测

回看第 0 步：索引副本一旦被污染，所有分数漂移却**不报错**。没有评测单子，你分不清「策略生效了」和「索引坏了」。所以顺序是固定的——先修可信度（幂等、去重），再建评测单子，最后才是改策略。难点全文见 [`index-difficulties`](https://github.com/quanttide/quanttide-search-lab/blob/main/docs/index-difficulties.md)，实测数据与选型见 [`tech-notes`](https://github.com/quanttide/quanttide-search-lab/blob/main/docs/tech-notes.md)。
